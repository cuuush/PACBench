## Gauntlet and execution contract

Pizza Day remains the smoke test; Pizza Week is intentionally a compact edge-case gauntlet, not a representative week of ordinary life. Pizza Month is the realism condition. Source sentences should still be intelligible and causally coherent, but density is intentional.

The week is October 5–11, 2026 in America/New_York. Pizza lunch changes across a group, a DM and email; Devon's evening pizza remains an independent simple control. Ben's dinner moves through an email reply with old quoted text. Friends' work, a houseguest, a workshop and small obligations supply distinct, bounded threads. Sunday introduces a separate next-Friday pizza lunch. Chatter concerns balloons and films without inventing outings. Messages vary in length and participation; Leo is genuinely silent until Tuesday at 10 am. No hidden acceptance is asserted.

The revision retains **48 scenes: 40 supplied scenes with 102 exact messages, and eight writer scenes bounded to 17–29 messages in total** (119–131 projected messages). Generated dialogue does not yet exist. Bounds limit source volume, not inference cost. Silence, the short delayed reply, emoji acceptance, ambiguous cancellation, dated quotations and critical state transitions remain exact. Ordinary exchanges use the writer where wording is flexible: `evening-control`, `namesake-reed`, `namesake-chen`, `jen-answer`, `concert-companion`, `ben-distinct-mail`, `proofreading-done`, `small-future-plan`.

Each writer scene owns its conversation, facts and small message range. **This spec omits top-level `noise` and requires the scene-defined default implementation at [`fdf90764`](https://github.com/cuuush/PACBench/commit/fdf90764f9945f2c6d3e9150b6b0c256efcdf38b), on `fix/scene-defined-noise`, or a descendant containing that change.** With that implementation, omitted noise resolves to authored/no-quota mode for scene specs. All 48 compiled scenes and the complete resolved spec/checks were checked equal to the prior explicit `noise: authored` version. On the older implementation, omission defaults to `low`; do not prepare this revision with old main or the review branch's unchanged runtime. Integrate the default change before this spec is used. No application code is included in this spec revision.

Exact-source scenes bypass the writer. Generated scenes still need source review, and all scenes require verification, contract review and the normal freeze gate.

There are **37 questions: 20 intermediate and 17 final**. Each intermediate checkpoint follows the 03:00 import of the previous day's sources and precedes its day's first new source message. Monday October 12 final questions follow the seventh source day's ingestion. Omit `ingestion_days`: that field requires final-only checks and would erase the intended intermediate-state tests. Run only with a harness path that actually supports these interleaved checkpoints; inspect the compiled schedule and readiness before any paid execution. A runner that ingests all seven days first is incompatible. Never let a failed import become a semantic failure.

The local native runner wires `import_before_check` into `run_checks` in `pacbench/native_pilot.py`; it selects only source batches ready at the checkpoint. This supports the proposed structure, but actual readiness still needs execution receipts. `native_resume.py` currently limits ingestion resume to final-only questions, so that resume path cannot be assumed for this variant.

Only `lunch-continuity` resumes across days; every other conversation ID starts fresh. The two Wednesday lunch questions compare resumed versus fresh sessions. Repeated questions can themselves become captured provider context: this experiment tests interactive state tracking, not pure passive final-only retention. Do not compare its scores directly with the existing final-only variant or count correlated questions as independent cases. Preserve the existing simpler specs as controls.

## Question and coverage changes in this revision

- 31 of 37 public prompts simplified; criteria revised for 22 turns. Question IDs and checkpoint times remain unchanged. Questions ask for plans, people, dates, status or links; none tells the model to compare a suspected duplicate with the “right” event or warns about a stale quote.
- Correct answers need not explain unrequested traps. In particular, the support URL need not mention the webinar; the visit answer need not mention the museum; October 16 lunch need not compare October 9; the companion answer need not describe Nora’s separate party. History is scored only when explicitly requested, as with lunch changes. Ben’s final-dinner question grades only the agreed dinner, not the discarded dates.
- The studio cancellation deliberately remains unresolved before clarification. A short “the message doesn’t identify which booking” is sufficient; neither a guess nor mandatory follow-up wording is required.
- Source wording no longer announces that the newsletter is not an RSVP, that an old preference is “obsolete,” or that a support link is not the webinar. Ordinary quotation provenance, original dates, sender/thread identity and the correction sequence establish the answer. Nora’s complete guest list names Nora, Eli and Jo rather than explicitly excluding the user and Devon.
- Eight flexible exchanges are now writer-authored scenes, not prewritten dialogue. Critical exact exchanges remain supplied. All generated coverage remains contingent on source review; criteria and coverage status cannot substitute for realized source evidence.
- C01–C35 statuses remain 18 drafted semantic cases, 11 partial, one integration qualification, five deferred. C22 remains person-cued recall, not a saturated-history or spontaneous-discovery test. No increase to measured coverage is claimed.
