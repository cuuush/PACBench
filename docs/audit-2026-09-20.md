## 0. Hermes patching: fork vs tracked diff (implementer's question)

No fork exists. The mechanism is: pinned upstream (`vendor/HERMES_PIN`,
`0348a19`) + pristine clone + tracked unified diff
(`patches/hermes-isolated.diff`, 6 files, +89/−5) + reapply recipe
(`patches/APPLY.txt`, one `git apply` command) + manifest hashes
(`hermes_pin`, `hermes_patches_sha256` in every run manifest via
`harness.run_manifest`) + integrity tests (`tests/test_vendor_patch.py`:
HEAD==pin, tree-diff==tracked-diff byte-for-byte, exact file list, no
scenario/answer-key/provider tokens in the patch, manifest records both).

My judgment: a fork adds review surface without new guarantees — upstream
is public, the pin is exact, and the byte-equality test fails on any drift
(hand edit or upstream pull) until the diff is regenerated deliberately.
The diff IS the patch, and it is the thing reviewed. Keeping tracked-diff.

## 2. Implementing vs optimizing the five lives?

Both. Deliberate corpus/grader changes driven by observed dev-life
failures (all committed with reasons, none hidden):
- YESNO first-cue polarity (`a7c3d8b`): pilot answers with incidental
  affirm words ("confirmed") misgraded.
- From-framed history + declined-mention traps (`653a49c`): "moved it
  from 7pm" and "you passed on the festival" misgraded.
- YESNO opposite-polarity forbidden + full→scoped polarity, historical
  confabulation fallback, topic-vs-pure cues, splitter negation fix,
  cue normalization (`ed0c2e3` + follow-ups): found by offline-grading
  new rubrics against adversarial phrasings.
- concert-rsvp DATE/'' → YESNO-status + DATE atoms (co-author ruling).
Per the split doctrine these lives are exposed forever: 5 dev lives are
debugging material, and no held-out life has been inspected (none exist).
`SplitDeclaration` pins the table; moving a life is a deliberate edit.

## 3. Unit of independence: lineage of the nine lives

- `poker-move` / `poker-unchanged`: SAME incident family
  (write-time-recency bet + its no-move control). One lineage.
- `weekend-plans` / `dentist-friday`: SAME incident family
  (implicit-context bet + control). One lineage.
- `dentist-depth`, `poker-collision`, `coat-weekend`, `reunion-thread`,
  `revoke-week`: five independent story families (no shared incidents,
  organizers, or venues across families).
So: 7 lineages across 9 lives, not 9 independent units. Story-family
leakage checks (comparative-gates.md gate 4) are NOT implemented — flagged
open; current corpus is small enough to audit by eye (this table), which
will not scale.

## 4. Leakage trace (one checkpoint end to end)

`coat-weekend/coat-reminder`: authoring beats (`life_c_coat.py`, drafts +
`must_include`) → `build_life` splits public `Life` from `SupportManifest`
(`authoring.py:101-157`) → adapters receive ONLY `o.public()` dicts
(`manifest.public_observations`; `Observation` cannot carry expectations —
`test_pacbench.py::ObservationsAreImmutablePublicData`) → memcal adapter
refuses rubric keys at ingest (`FORBIDDEN_OBS_KEYS`, tested by
`test_ingest_refuses_rubric_payload`) → Hermes turns see only the user
prompt (`checkpoint.public_prompt()` returns JUST the question) →
grading joins answers to the hidden rubric offline (`grade_answer`) →
report aggregates grades, never evidence. Hard boundaries: type-level
(Observation has no expectation fields), runtime (ingest refusal,
dispatch allowlist), and test-level (`HiddenKeysStayHidden`,
`PACBenchIsMemcalFree`). Scenario IDs (`coat-weekend/...`) never leave
the harness: adapters see `source_id`s like `wa-f003`, which are
content-free serials. Residual risk (stated, not hidden): Hermes driver
memory is session-scoped per episode; cross-episode leakage is prevented
by fresh scratch homes per run (`preflight` refuses live-looking paths).

## 7. Four clocks distinct

`Observation` carries `written_at` / `arrived_at` / `collected_at`
(`observation.py`); event time is message content, never a clock field.
`chronology_ok` rejects written>arrived or arrived>collected
(`test_pacbench.py::CollectionChronologyHolds`); exposure follows

arrival is exercised (dentist stale reminder arrives after the rebook;
authoring supports `arrival_delay_min` / `collection_delay_min` per
beat). The hardest-case machinery (old confirmations arriving late)
exists in Life A/D; eight-step histories do not (Q20).

## 19. Duplicate delivery, four ways

  external_id) DO NOTHING`, memcal `archive.py:42`; lexical same-key
  semantics; `archived N/M` counts in usage notes expose drops).
- Different ID, identical content: NOT deduped (two rows) — stated
  limitation; graders handle it via forbidden stale values.
- Quoting an old message: stored as its own row (new evidence, new ID).
- Independently repeating stale info: stored as its own row; the Alex
  stale-repeat beats exist precisely for this (`wa-stale`, email-stale).
Tests distinguish 1 (idempotence test in lexical adapter tests) and 4
(stale-repeat checkpoints); 2-vs-3 conflation is untested (gap).
