# PACBench agent guide

## Priorities and budget

Realism is the first priority. Benchmark practical local memory backends with authentic daily document or message ingestion. Hermes only answers later questions using the selected provider's normal context and exact shipped tools. Start with small Pizza Day, then corrections over two days, two independent plans over three days, roughly 100 extra messages, and only later 1000. Never pad dialogue or generate 100k lines.

Use **Spark Contributor** through `/workspace/muse-gateway` for every live authoring, judging, Hermes and provider inference call. The gateway has a hard **$10 per UTC day**, resetting settled daily spending at midnight UTC, with **no lifetime cap**, as explicitly clarified by the user on 2026-10-11. Unknown charges stay held across days. A daily monetary refusal is terminal until the next UTC day; never reset the ledger, alter project labels to evade it, or bypass the gateway. Durable ledger and credentials live in `/workspace/shared/muse-gateway`, outside Git. Check the cost boundary before live work. Unknown charges retain reservations; never fall back upstream or call an unmetered hosted service.

Development results are disposable. Keep only the most recent Pizza Day trial and necessary source/authoring/audit evidence. Delete old runs, caches, snapshot reports, dead execution paths and compatibility branches. Do not add historical invalidity UI. Preserve current failure evidence while diagnosing it; never relabel failure as success. Preserve installed runtime dependencies, the spending ledger and unrelated user files.

## Authentic ingestion and recall

- Memcal uses its native iMessage reader and processing against a provider-independent Apple Messages SQLite fixture and separate contacts source. Preserve realistic GUIDs, Apple timestamps, service fields, sender handles, chat membership and joins. Future provider connectors must be able to reuse the fixture unchanged.
  Email uses provider-independent RFC 5322 messages through a real local TLS IMAP fixture and Memcal's native reader. Inbox/Sent ownership, Message-ID/reply references, dates and separate Contacts account identities must remain consistent. No Bridge-method replacements or direct archive insertion.
- Configure providers from project recommendations, using isolated run-owned identities/stores. Queue acceptance is not completed ingestion. Honcho uses native `session.add_messages`, source peers and timestamps, and the configured non-speaking Hermes observer joined before messages (using native observation flags verified by the API), the native 16384-token output setting for Spark reasoning (2500 was observed truncating extraction), and the documented local flush option. For a finite isolated daily import, check only submitted sessions: allow up to 15 minutes with a five-minute stall bound and a 17-minute worker bound, saving only status changes. This benchmark barrier is not a production requirement that a continuously active workspace queue empty. Record bounded readiness checks and fail before recall when processing is incomplete. Exclude cloud-only or impractical ingestion backends; see [provider map](docs/document-ingestion-provider-map.md).
- Set native process `TZ` to the frozen scenario's named timezone; Eastern means `America/New_York`, with seasonal offsets. Memcal's native nightly clock is 03:00 local. Never evaluate earlier questions against future source or processing state.
- Recall begins without prior Hermes source conversations or populated built-in memory. Run the normal CLI in an empty directory outside every Git project. Do not use `--ignore-rules`: it also disables external memory hooks. Audit Hermes's actual saved system prompt and working directory; benchmark project context must never reach the answering agent.
- New trials use `provider-memory-with-source-penalty-v3`, as the user authorized on 2026-10-12. Expose only the selected provider's exact shipped schemas, including native message/archive/source readers and OpenViking's mixed `viking_read`. Correct source-assisted answers keep their semantic grade but earn zero retention credit; carry that source path into dependent turns sharing the context. Log actual calls, latency, models, tokens and costs. Memcal's normal `memcal_open`, retained pages, generated summaries and attached citations receive normal credit. Honcho native journals expose internal tools; publish sanitized tool inputs/results, never raw prompts/private reasoning. Explicit-query matches can establish source fallback; asynchronous source work without proven attribution needs review and remains uncredited. Disable built-in memory, session search, discovery/dispatch, filesystem, shell, browser and outside connectors. Block non-provider attempts before execution even if the answer is correct. This is a tool boundary, not an OS sandbox. The current published run used the earlier `retained-memory-only-v2` condition; audit its frozen permissions without relabeling its results.
- Fix Memcal product bugs directly in `/workspace/memcal`; commit there and push when requested. Do not hide native bugs with provider-specific benchmark workarounds. Benchmark changes belong in PACBench. Commit coherent checkpoints and final code; never commit credentials, private homes, databases or encrypted artifacts.

## Authoring, questions and judgment

- Author weeks as one JSON file with `noise`, reusable `channels` (source type, participants, optional group name), and `days` keyed `monday` through `sunday`. Scenes use a channel reference, human-readable `time`, short `scene` and inline English `facts`. Assistant turns use public `prompt` and an English `expect`; no top-level fact catalog or fact-ID matching. `--week-start` assigns concrete Monday dates during preparation. Preserve authored times and freeze timezone offsets.
- Noise is only `low | medium | high`. Low stays minimal; medium targets ordinary chatter; high targets 600–800 messages per person per conversation per day. Never pad, copy or truncate dialogue. Use bounded chunks for large scenes, but test low first. No separate noise file or generated noise conversations.
- Verify generated dialogue and freeze evidence-cited criteria and exact questions before provider execution. The semantic judge derives independent criteria from English expectations; code checks shapes, IDs, citations and hashes. English criterion drafts rejected by a well-formed independent review get one revision using that feedback and a new independent review. Exact authored facts cannot be silently altered. Unsupported/unfair criteria still prevent a runnable corpus. Private authoring material never enters Hermes questions or provider imports.
- Pizza Month will import once daily for 30 days and ask only after the month; do not insert interim questions. Start with low-noise daily batches and reuse frozen generation. Preparation emits one portable `week.json`; provider execution reuses it without writer/verifier calls. Resume only unchanged verified scenes when repairing preparation. Import daily source batches chronologically: a question cannot see future sources or future native processing.
- Named conversation IDs resume real Hermes sessions; different IDs start fresh while provider memory persists. Planned public user turns use normal provider capture. Earlier answers resolve references but cannot earn facts missing from the current answer. Scripted clarification replies run only when requested. Bind dependent checks to delivered replies; never assume an undelivered update occurred.
- Memory trials judge remembered facts, event identity, current state and change history. Do not require a preferred assistant policy such as clarifying rather than cancelling both outings, a particular tool choice, warning, tone or acknowledgement. A response naming both outings demonstrates awareness of both, regardless of how it interprets a cancellation request. Keep behavioral/action tests explicitly separate from memory conclusions. Count distinct outings, not repeated mentions, participant invitations or updates to the same outing. Use natural questions and only the authored expected details as criteria.
- Grade observable behavior pass/fail. Acknowledgement alone proves neither persistence nor an external action; check state later in a fresh session. Missing script truth, malformed judges and execution errors are ungraded with reasons. Continue independent conversations; skip unavailable dependencies with a cause. Never let one failure erase a week. Review passes and failures during development.
- Freeze recovery policy before arms run. Zero initial correct facts, wrong values, admitted lookup failure or a missed explicit request gets no follow-up. Otherwise Spark writes ONE short message asking for ALL silent implicit omissions, given only original question and those facts, with one independent coverage/leakage review. Reuse frozen wording across matching missing-fact sets. A rejected draft can receive one independently reviewed revision before delivery. No per-fact questions upfront; no second attempt.
- Keep initial grades unchanged; recovery earns half credit separately. Retained event/page detail may recover a fact. Native source readers are permitted with the source penalty; outside tools still fail the check. Unknown operations get no retention credit pending review. Separate ingestion, initial turns, follow-ups and shared authoring/judging overhead. Provider work after an answer may be capture/consolidation rather than lookup; deferred work is not free. Measure whether Memcal is cheaper without assuming it wins. Log calls, arguments/results, failures/repeats, latency, actual token deltas and gateway windows. Unknown provider work or tool cost stays unknown. Stop further paid checks in an arm after three definitive provider-side HTTP 400/422 responses; keep the native completion receipt and held costs, mark execution ungraded, and continue independent arms. Pending requests or successful responses without usage do not trigger this barrier.
