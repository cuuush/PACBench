## Gauntlet and execution contract

Pizza Day remains the smoke test; Pizza Week is intentionally a compact edge-case gauntlet, not a representative week of ordinary life. Pizza Month is the realism condition. Source sentences should still be intelligible and causally coherent, but density is intentional.

The week is October 5–11, 2026 in America/New_York. Pizza lunch changes across a group, a DM and email; Devon's evening pizza remains an independent simple control. Ben's dinner moves through an email reply with old quoted text. Friends' work, a houseguest, a workshop and small obligations supply distinct, bounded threads. Sunday introduces a separate next-Friday pizza lunch. Chatter concerns balloons and films without inventing outings. Messages vary in length and participation; Leo is genuinely silent until Tuesday at 10 am. No hidden acceptance is asserted.

The source is small: **120 messages, 1,207 whitespace-delimited words (6,753 body characters), across 18 channels**. All 48 scenes contain exact sender/body/offset-bearing timestamps; source messages are inspectable before any paid preparation. Private facts and expectations never belong in provider inputs. `noise: authored` adds no automatic quota, and supplied messages bypass only the writer. Scene verification, source-only coherence/answerability review, contract review and the normal freeze gate are still required.

There are **37 questions: 20 intermediate and 17 final**. Each intermediate checkpoint follows the 03:00 import of the previous day's sources and precedes its day's first new source message. Monday October 12 final questions follow the seventh source day's ingestion. Omit `ingestion_days`: that field requires final-only checks and would erase the intended intermediate-state tests. Run only with a harness path that actually supports these interleaved checkpoints; inspect the compiled schedule and readiness before any paid execution. A runner that ingests all seven days first is incompatible. Never let a failed import become a semantic failure.

The local native runner wires `import_before_check` into `run_checks` in `pacbench/native_pilot.py`; it selects only source batches ready at the checkpoint. This supports the proposed structure, but actual readiness still needs execution receipts. `native_resume.py` currently limits ingestion resume to final-only questions, so that resume path cannot be assumed for this variant.

Only `lunch-continuity` resumes across days; every other conversation ID starts fresh. The two Wednesday lunch questions compare resumed versus fresh sessions. Repeated questions can themselves become captured provider context: this experiment tests interactive state tracking, not pure passive final-only retention. Do not compare its scores directly with the existing final-only variant or count correlated questions as independent cases. Preserve the existing simpler specs as controls.

## Additional compact edge cases

- **N01 — bounded preference expiry without invented reversal.** `preference-correction` m3 limits Maya’s dairy-free trial to October 11 inclusive; `future-pizza` m3–4 leaves October 16 food undecided. `next-week-pizza` must not extend the old rule or infer she now accepts dairy. The owner’s independently corrected, open-ended preference remains dairy-free. This adds no scene or question.
- **N02 — third-party identity collision.** `future-pizza` m5 reports Nora’s separate Friday gathering at the same 6 pm Luigi’s time/place as the user’s Devon outing, explicitly excluding both from Nora’s invitation. `third-party-collision` checks no imported attendance or merged party. This adds one source message and one question; it reuses C05/C23 identity mechanisms without claiming an independent sample.

## Review and integration gates

1. Review exact messages as evidence. This is deliberately dense: 48 short scenes, several roles and repeated checkpoint questions. Density is intentional for the gauntlet; do not describe it as representative realism. Keep the simple evening pizza as a control, and report case families instead of inflated per-question sample sizes.
2. Inspect roster transitions, Nora's off-thread relays and Leo's silence; preserve the lack of replies to Alex Chen. Confirm every question's simulated time against *available* sources, not the whole final corpus. Preserve historical versus current facts and the distinction between plans and actual attendance/departure.
3. Before any paid work, coordinate the benchmark and Hermes branches. Import only this separate JSON and this matrix; never replace existing specs or relabel a frozen corpus. No changes to harness, Hermes, providers, defaults, ledger or old run evidence are needed for author review. This working tree is intentionally uncommitted/unpushed pending that coordination.
4. Preparation still needs current gateway state, normal verifier/contract/source-only review and freeze audit, plus source-level human review. Review every drafted criterion; no automatic approval is inferred from successful compilation. This task authorizes no paid preparation.
5. Use semantic negative controls during the later reviewed contract-validation phase: lunch at Rosa's or with Leo/Nora after Thursday must fail the affected criterion; unknown RSVP before acceptance should pass; definite acceptance before reply should fail; correct time with wrong venue should remain separably gradeable; “not known” attendance before evidence should pass; invented attendance should fail. Preserve any rejected contracts and their receipts rather than silently rerolling.
6. Separate follow-on fixtures are necessary for genuine delayed import, replay, faults/concurrency, native identity/policy changes, assistant contamination, DST/New Year, long-history saturation and recurrence beyond a week. No absence is hidden by a 35/35 claim. Existing scoped tests may inform these fixtures but are not provider benchmark results.
